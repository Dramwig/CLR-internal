# CLR 全局工程与审查约定

生效：2026-11-03（北京时间）。适用于本仓库每个新对话、恢复会话和后续里程碑；不是建议，也不因换对话而失效。开始工作前必须完整阅读本文件、根目录 AGENTS.md、docs/STATUS.md 和当前里程碑任务书。用户后续明确修订优先，须同步持久化；历史偏离不能作为继续偏离的许可。

## 定义与提案

CLR：`R(z, q, s) → p(a | z, q)`。z 为来自源模型 s 的潜在思维隐状态或 KV 消息；q 为 choice / score / yes-no 类型化问题；输出校准概率，并用 split conformal 给出预测集。

先通读 [Idea B 提案](IdeaB_Calibrated_Latent_Reader.md)（指向原文 [proposal.md](proposal.md)）。提案中的文献、新颖性、理论保证和预期效果不自动构成已验证结论；conformal 保证须明确可交换性等假设，分布偏移与自适应攻击下不得无条件宣称保证。

## 1. 代码结构与配置

- `clr/sources/`：每个源模型一个文件，`codi.py`、`coconut.py`、`huginn.py`、`latentmas.py`、`c2c.py`，统一接口；已冻结实现需变更时新增版本。
- `clr/data/`：潜对象 dump、问题库、标签生成、splits。
- `clr/models/`：adapter、reader 主体、输出头。
- `clr/calib/`：温度缩放、split / Mondrian / weighted conformal。
- `clr/baselines/`：question-only、线性/MLP 探针、LTO 式标量、Patchscope 式读取。
- `clr/search/`、`clr/audit/`、`clr/attacks/`：潜空间搜索、潜通信审计、攻击。
- `configs/`、`scripts/`、`tests/`、`reports/`：配置、入口、测试、报告。
- 所有实验由 YAML config 驱动，命令行只传 config 路径及覆盖项，不将实验协议藏在临时命令中。

## 2. 可复现运行

固定 seed。每次运行在 `runs/<run_id>/` 保存 config 快照、git commit、环境信息、种子、资源版本、日志及 `metrics.json`；指标必须可追溯到实际运行。不得编造、补造或把事后快照冒充启动时快照。

## 3. 禁止静默回退

模型加载失败、checkpoint 名称错误、显存不足等必须直接报错，并写入 BLOCKERS.md。不得偷偷替换模型或缩小设置。确需降级时明确原因、采用的设置及影响，并在报告中标注；遵循已有授权，不能把报错当作任意降级许可。

## 4. 划分与测试集隔离

- 一律按 problem / episode ID 划分，不能按样本、步骤或轨迹拆分同一题；划分保存为 `data/splits/*.json` 并冻结。
- 训练、验证、校准、测试分别管理；所有调参仅使用 val / cal，test 只在最终评估使用。
- **smoke 和调试一律使用 val 代理，不触碰 test。** 不得为功能检查、吞吐检查、排错或中间评估读取 test 样本、生成 test 预测或查看 test 指标。
- 训练 smoke 若需要训练样本，只能从训练 split 抽取；其中模拟最终评估的环节使用 val 代理。不得将 val 代理冒充最终 test 结果。
- 历史测试暴露如实记录，不通过更换划分、删除记录或挑 seed 掩盖。评测修正及影响写入变更记录。

## 5. smoke 关卡

每个里程碑先运行 smoke：数据量 ≤ 5%，运行时间 ≤ 15 分钟。明确实际数据规模、耗时和检查结果；通过后才能运行完整版本。smoke 仍受第 4 条测试隔离约束，不因规模小而豁免。

## 6. 里程碑记录与冻结

每个里程碑结束时必须：

- 在 EXPERIMENTS.md 追加：做了什么、命令、结果表（均值 ± 95% CI，随机实验至少 3 个 seed）、与预期的偏差、负面结果；长表放详细报告并链接。
- BLOCKERS.md 记录所有未解决问题、假设、降级与偏离，不能把未解决项写成已通过。
- `reports/Mx_<name>.md` 保存完整报告和图，附 CSV、run 等证据路径。
- 冻结已完成里程碑的代码和结果；后续变更新增版本（如 v2），不覆盖旧结果，保留版本关系和冻结清单。
- 延续已明确的统计约定：确定性评估按题 bootstrap 10,000 次给 95% CI；seed 用于含随机性的实验，不以重复确定运行伪造三 seed 区间。报告 CI 的单位、聚合方式和来源。

根目录 EXPERIMENTS.md / BLOCKERS.md 分别链接到 `docs/EXPERIMENTS.md` / `docs/BLOCKERS.md`，维护同一份记录。

## 7. 负面结果与指标诚实性

如实报告负面结果。不为结果好看而改指标定义、换划分、挑 seed 或选择性展示。区分预期、观察与推断；缺失的成本或结果明确标为缺失，不能当作零。

## 8. 计算成本与资源

记录 GPU 型号、GPU 小时及源模型前向次数，明确成本口径和是否包含 smoke、失败、重启。大型下载或训练前实时检查 GPU 与磁盘；优先复用共享数据和权重，项目派生产物保留在本项目。

按既有授权，需要空间时遵循 `/home/me/tools/disk-reserve/AGENTS.md`，用 `reserve.sh release <整数GiB>` 释放配重，使用期间保持自动填充暂停；不因磁盘余量低主动放弃任务。真实 I/O 错误仍须报错和记录。

## 9. 最小测试与输入约束

每个模块在 `tests/` 写最小单元测试，尤其覆盖标签生成、conformal 覆盖率、选项顺序不变性和划分无泄漏。不得只证明程序能运行而忽略标签与协议正确性。

延续 M2–M3 起的全局约束：reader 和所有基线（含 B5）不看源问题文本，只读观测状态/前缀与类型化模板、选项；读取实际输出的 z_t，不读取加噪后的输入向量。指标并列报告 reader_val（源训练分布）和 test（未见分布），Q1 在 reader_val 另分 clean / traj。Q1 起点与后续状态的具体标签规则继续按已确认任务书执行，不把更早干净前缀错标为既定策略的样本。

## 10. 从 M4 起的唯一审查交付

每个里程碑额外生成 **`reports/Mx_REVIEW.md`，这是唯一发给审查者的文件**。详细报告照常保存在仓库里，但不要求发送；审查摘要通过路径索引详细证据。此规定不是授权自动向外部收件人发送消息。

审查文件必须 ≤ 8KB；按 UTF-8 文件字节数检查，保守执行 ≤ 8,000 字节。固定结构、顺序如下：

### (a) 状态一句话

清楚区分完成、未完成、待审查；不能把运行启动写成完成。

### (b) 关卡清单

逐项写“通过 / 未通过”及关键数字。未执行、缺证据的关卡写“未通过（未执行/缺证据）”，不省略失败项。

### (c) 核心主表（最多 3 张）

只放 test 和 reader_val 的核心指标；数字保留 **3 位有效数字**（不是 3 位小数）。不放逐层或逐 t 的大表，详细数据放报告/CSV。精确 run ID、路径和配置标识不按有效数字规则截断。

### (d) 本里程碑新增的偏离与阻塞

只写本里程碑新增项，不复制历史条目；需要背景时链接历史记录。无新增时明确写“无”。

### (e) 需要审查者决定的问题

只列实际待决定事项；无则写“无”，不制造审批问题。

### (f) 证据路径

列详细报告、CSV、run 目录路径，使数字与结论可查证。

同时：EXPERIMENTS.md / BLOCKERS.md 继续追加，但**每条新记录 ≤ 10 行**；长内容放报告再链接。历史长条目保留，不为新格式改写冻结历史。不得通过把同一长记录拆成多条来规避限制。

## 新对话入口与状态维护

每个新对话都必须遵守本文件，不能仅凭聊天摘要或历史日志启动实验。先读取 AGENTS.md 的索引、本文、STATUS.md 及当前任务书，再核实冻结状态与资源。AGENTS.md 保持规则入口和简要当前状态；完整接续、实验、阻塞和变更分别落入 docs 下相应文档。里程碑特定设置只约束该里程碑，不把 M2–M3“未训练 CLR”等历史范围限制误用为 M4 的永久禁令。
