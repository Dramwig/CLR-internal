# M5a 潜空间搜索可行性（2026-11-05，北京时间）

用户明确授权与 M4.1 并行，在 CLR 修复前用 oracle / 现有探针判断价值函数路线的可行性。本授权是此前 G1 前不启动 M5 的 **M5a 专项例外**，不代表 G1 通过，也不启动完整 M5/M6。

## 冻结任务

- 仅 CODI-GPT2 的冻结 val300；不读取 test 内容、预测或指标。源模型 fp32、temperature=0，保留同一原 cohort 的左 padding / 绝对位置 / KV 协议。
- 从观测状态 z_t 用 `clr/policy.py` 所用的 `RelativeNoise` 生成候选，sigma=1.5；先经源模型一步得到 z_(t+1)，价值函数只读该实际观测。
- N={4,8,16}；S0 greedy，S1 N 条独立 π 轨迹多数投票，S2 终点 Best-of-N，S3 每个父节点扩展 N 条、全局保留 top-b，b={2,4}。
- 价值函数 B4 / B3(Q1) / oracle；复用 M3 三个 seed11/22/33 的冻结 checkpoint。B3 使用第一个已有 Q1 模板，无原题/gold 文本输入；单调校准不改变单模板排序。
- oracle 对每个候选 K=16 独立 π MC rollout；其 gold 只进入 oracle 的行为打分。终点无剩余潜步骤，K16退化为相同的贪心答案正误，须明确其特权性质。
- 全搜索 t=0..5；早期搜索 t=0..3，后两步每个保留分支仅沿 π 继续，不再扩展/中途筛选，终点仍按同一价值函数选一个分支。S1/S2 无中途选择，两个 horizon 只作独立随机面板。
- 相同 seed/题/N/b/horizon 的候选噪声不依赖价值函数；并列分数按固定生成顺序，投票并列取最早合法答案，非法解析不作为正确答案或有效投票。

## 成本与统计

- 总上限10 GPUh，含加载、smoke、失败/重启、基准及完整运行。先≤15题且≤900秒val smoke，实测外推后才允许完整运行。
- 主轴采用每题源模型 lane 前向次数，含prefill、潜步骤和答案解码；记录物理batch调用次数及padding/结束后仍占据batch的成本。probe前向换算为源一步等价成本；oracle内部所有K16成本单列且计入主轴。
- S1除N4/8/16主面板，还生成独立长投票池，覆盖实际搜索成本；按每题累计成本取预算以内最长前缀。若4096轨迹仍不足，明确标缺，不把欠花预算的曲线称严格匹配。
- 共同预算点预设128,256,512,1024,2048,4096,8192,16384,32768；不按准确率挑N/b/horizon。原始配置点全部保留；共同预算规则须在报告生成前固定。
- 三seed全部纳入；按题配对bootstrap10,000次报告95%CI，seed均值先在题内聚合。可用 oracle 增益为正且有证据时才报告“拿到上限比例”；分母接近0/不确定时标不可解释。
